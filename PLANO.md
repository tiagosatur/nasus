## 1. Estratégia

### Contexto

O nasus.digital é o destino de autoridade da operação de prospecção iniciada com medspa-leads.
Quando um prospect recebe o relatório de pitch via WhatsApp, a próxima ação dele é
pesquisar quem mandou. O site precisa:

1. **Confirmar credibilidade** em < 5 segundos acima da dobra
2. **Reforçar o argumento** do relatório (seu site está perdendo clientes)
3. **Converter** — agendar conversa / WhatsApp

Futuramente: plataforma para vender produtos digitais e expandir para mercado internacional.

### Posicionamento

> "Você aparece no Google quando um cliente procura o seu serviço?"

Não vendemos "site bonito". Vendemos visibilidade, leads, clientes.
Cada serviço é apresentado em termos de resultado de negócio, não de entregável técnico.

---

## Nichos-Alvo

O foco é **profissionais liberais com alto ticket, dor clara de visibilidade e facilidade de demonstrar ROI**.
O site é generalista o suficiente para atender todos, mas a prospecção ativa começa pelo nicho 1.

### Nicho 1 — Estética & Saúde (prospecção ativa via medspa-leads)

**Quem:** Clínicas de estética, dermatologistas, dentistas com foco estético,
harmonizadores faciais, cirurgiões plásticos, nutricionistas estéticos.

**Dor:** Aparecem na página 2-3 do Google enquanto concorrentes faturam com os mesmos
procedimentos. Paciente novo pesquisa "botox em [cidade]" e não os encontra.

**Por que converte:** Ticket alto por procedimento (R$ 500–5.000+), retorno recorrente
do paciente, mercado em expansão, fácil calcular ROI ("um paciente a mais por mês paga o serviço").

**Canal de prospecção:** medspa-leads (automatizado — busca, analisa, gera pitch, envia WhatsApp).

---

### Nicho 2 — Direito

**Quem:** Advogados autônomos e pequenos escritórios (trabalhista, família, previdenciário,
imobiliário, criminal). Especialmente os que dependem de clientes pessoa física.

**Dor:** OAB restringe publicidade agressiva, então SEO e presença orgânica são a principal
forma legítima de captar clientes. A maioria tem sites de 2015 ou nenhum.

**Por que converte:** Ticket alto (honorários), cliente busca "advogado trabalhista em [cidade]"
com intenção de contratar, baixa concorrência digital qualificada no segmento.

**Canal de prospecção:** busca manual no Google + LinkedIn Outreach (adaptar medspa-leads).

---

### Nicho 3 — Odontologia

**Quem:** Dentistas com serviços de alto valor — implantes, facetas, clareamento, ortodontia
estética (alinhadores). Clínicas que querem crescer além do convênio.

**Dor:** Mercado saturado de dentistas, diferenciação vem de aparecer bem no Google e ter
site que transmite confiança. Muitos dependem só de indicação e não têm presença digital.

**Por que converte:** Ticket altíssimo (implante R$ 3.000–8.000/unidade), paciente pesquisa
antes de escolher, site e reviews são decisivos. SEO local é direto ao ponto.

**Canal de prospecção:** adaptar medspa-leads com keywords de odontologia estética.

---

### Nicho 4 — Coaches, Consultores e Infoprodutores

**Quem:** Coaches de carreira/executivos, consultores de negócio, terapeutas, psicólogos,
profissionais que vendem sessões, mentorias ou cursos online.

**Dor:** Dependem 100% de Instagram ou indicação — sem presença no Google, sem landing page
que converta tráfego pago, sem funil estruturado.

**Por que converte:** Alta disposição para investir em marketing (já pagam tráfego pago),
entendem de resultado, ciclo de venda rápido, ticket de setup + landing page bem definido.

**Canal de prospecção:** LinkedIn Outreach, Instagram DM, indicação de clientes de outros nichos.

## 2. Serviços Oferecidos

| Serviço | Posicionamento | Ticket |
|---|---|---|
| **Presença Digital** | Site institucional moderno + PageSpeed 95+ | R$ 2.000 – 5.000 |
| **Google Meu Negócio** | Perfil GMB otimizado: fotos, categorias, posts, gestão de reviews | R$ 300 – 600/mês |
| **Presença Contínua no Google** | SEO local + GMB + AEO (IAs) todo mês | R$ 500 – 1.200/mês |
| **Pacote Completo** | Site + Presença Contínua (2 meses inclusos no setup) | R$ 3.000–8.000 setup + mensalidade |
| **Landing Page** _(upsell)_ | Página para converter tráfego pago (Google Ads / Meta) | R$ 1.500 – 4.000 |

> **LP é serviço avulso, não parte do sistema base.** Pressupõe que o cliente já investe em tráfego pago — conversa diferente do cliente que quer visibilidade orgânica. Oferecer como upsell após o site estar no ar.

> **Sistemas customizados (agendamento, CRM, integrações) estão fora do escopo da Nasus.** Perfil de comprador diferente, ciclo de venda longo, posicionamento incompatível com o site atual.

**Upsell natural:** Site → GMB + Presença Contínua → retainer mensal = receita recorrente previsível.
**Meta:** 20 clientes recorrentes × R$ 800/mês = R$ 16.000/mês

### Decisão de preço no site

**Não mostrar tabela de preços.** O mercado de serviços locais (agências, freelancers) não mostra,
e o ciclo de venda passa sempre por uma conversa onde o contexto importa.
Mostrar "a partir de R$ X" pode filtrar leads prematuramente antes da call de diagnóstico.
CTA direto para conversa qualificada — o preço é apresentado na proposta personalizada.

## 3. Estrutura da LP

### Seção 1 — Hero

**Objetivo:** Fazer o prospect se identificar em < 3 segundos.

Copy principal:
```
Seu concorrente está na primeira página do Google.
Você, não.
```

Sub-headline:
```
Sites que ranqueiam, convertem e trazem clientes reais.
Para clínicas e profissionais que levam o negócio a sério.
```

CTA: "Ver como funciona" (scroll) + "Falar agora" (WhatsApp)

Animação: texto que entra com SplitText char-by-char, cursor piscando no final.
Background: dark #111, grain texture sutil, uma linha dourada que cresce horizontalmente.

---

### Seção 2 — O problema (sem site ou site ruim)

**Objetivo:** Ampliar a dor. Fazer o prospect concordar antes de vender.

**Implementado:** Diferente do planejado original. Estrutura atual:
1. **Headline impactante** — "Hoje à tarde, alguém na sua cidade buscou o seu serviço. E ligou para o concorrente."
2. **Três pain points** (Refém / Invisível / Desperdiçado) — linha do tempo horizontal com palavra-impacto em itálico
3. **Dois canais** lado a lado com mockup interativo:
   - Google Search — lista de resultados com "Você não aparece aqui."
   - IA (ChatGPT/Gemini) — mockup de chat com "Você não é citado aqui."

Animação: ScrollTrigger com stagger em cada bloco.

---

### Seção 3 — A solução (o que fazemos)

**Objetivo:** Apresentar os serviços como peças de um sistema coeso.

Sistema visual com 3 camadas (grid de cards):

```
CAMADA 1: Fundação        → Site moderno (PageSpeed 95+)
CAMADA 2: Descoberta      → SEO Local + Google Meu Negócio (Maps + busca orgânica)
CAMADA 3: Autoridade      → AEO (IA search) + otimização contínua
```

Landing Page não entra nas camadas — é serviço complementar para quem já faz tráfego pago (ver Seção 2 — Serviços).

**Implementado:** Grid de 3 cards estáticos (sem expand/collapse). A camada 02 já inclui "Google Meu Negócio" nos tags.

Animação: stagger de entrada com ScrollTrigger.

---

### Seção 4 — Prova (dados do diagnóstico, não depoimentos)

**Objetivo:** Credibilidade sem depender de cases de clientes ainda inexistentes.

**Estratégia de lançamento:** Usar dados reais do medspa-leads como prova de processo.
Não inventar depoimentos — isso destrói credibilidade se descoberto num nicho onde
profissionais se conhecem. Substituir por números verificáveis:

```
Analisamos 200+ clínicas em Curitiba.
78% estão invisíveis no Google — fora da primeira página.
```

Complementar com benchmarks de mercado e o próprio nasus.digital como prova técnica:
- "Este site tem Lighthouse 100. É o padrão que entregamos."
- Métricas do medspa-leads: cidades analisadas, clínicas mapeadas, % sem site ou com PageSpeed < 50

**Quando tiver o primeiro cliente real:** substituir pelos dados reais dele (com autorização).
Nesse momento a seção vira o modelo clássico de antes/depois com métricas específicas.

Animação: número counter animado ao entrar no viewport.

## 5. Animações (GSAP)

### Princípios
- Nada pisca ou chacoalha. Tudo é **intencional e suave**.
- Duração padrão: 0.6–1.0s com ease `power2.out` ou `expo.out`
- ScrollTrigger em todas as seções — nada anima sem o usuário ter chegado lá

### Animações planejadas

| Elemento | Técnica GSAP | Efeito |
|---|---|---|
| Hero headline | SplitText + stagger | Chars entram um por um, fade + translateY |
| Linha dourada | from width: 0 | Cresce da esquerda para a direita |
| Cards do problema | ScrollTrigger + stagger | Entram em sequência, fade + translateY |
| Linha conectora dos cards | DrawSVG | Linha que se desenha conectando os steps |
| Camadas da solução | ScrollTrigger + expand | Expand/collapse com altura animada |
| Counters de resultado | ScrollTrigger + counter | Números sobem de 0 ao valor real |
| Steps do processo | ScrollTrigger pinning | Seção fixada, linha avança com o scroll |
| Cursor customizado | gsap.ticker | Cursor com lag/lerp suave |
| Hover nos CTAs | scale + glow | Botão cresce levemente, aura dourada aparece |

- **Grain overlay:** desativar em mobile (custo de renderização sem ganho visual)
- **Testar em:** iOS Safari (webkit scrolling), Chrome Android, viewport 375px e 390px

## 7. WhatsApp — Qualificação Automática de Leads

Quando o lead clica em "Falar no WhatsApp", não vai para um chat vazio.
O link `wa.me` carrega uma mensagem pré-preenchida que já inicia a qualificação:

```
Olá! Vi o site da Nasus e quero entender como posso aparecer melhor no Google.

Meu negócio: [nome da clínica/escritório]
Cidade: [cidade]
```

Isso força o lead a se identificar antes mesmo de você responder.

**Resposta automática (WhatsApp Business — configuração nativa, gratuita):**

```
Olá! Recebi sua mensagem e já vou analisar sua presença digital.

Para agilizar, me responde rapidinho:
1. Qual é o seu site? (se tiver)
2. Qual serviço você mais quer que os clientes te encontrem?
3. Em qual cidade você atende?

Retorno em até 2 horas com um diagnóstico inicial. 🔍
```

Essa sequência qualifica o lead (tem site? qual nicho? qual cidade?) sem nenhum esforço seu
e chega na call já com contexto para personalizar a proposta.

**Evolução futura:** Typebot (gratuito) integrado via Zapi — chatbot estruturado que
coleta as respostas, salva num sheet e notifica você. Só implementar quando o volume justificar.

## 8. SEO + AEO + GEO — Estratégia de Visibilidade

O site precisa praticar o que vende. Em 2026, "SEO" não basta — busca se fragmentou em três superfícies que exigem otimização coordenada:

- **SEO** — busca tradicional (Google, Bing) — rankings, indexação
- **AEO** (Answer Engine Optimization) — AI Overviews, snippets, answer boxes
- **GEO** (Generative Engine Optimization) — ser citado por ChatGPT, Claude, Gemini, Grok

> SEO entrega tráfego. AEO entrega resposta. GEO entrega autoridade.

Conforme pesquisa de 2026: sites que executam as 3 camadas juntas (técnica + conteúdo + autoridade) conquistam citações em 4-8 semanas. Quem faz só uma raramente é citado.

### 8.1 Camada técnica (fundação)

**robots.txt** — liberar explicitamente AI crawlers (sem isso = invisível pra IA):

```
User-agent: GPTBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: ChatGPT-User
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: Claude-SearchBot
Allow: /

User-agent: Google-Extended
Allow: /

User-agent: *
Allow: /

Sitemap: https://nasus.digital/sitemap.xml
```

**Schema.org JSON-LD** no `app/[locale]/layout.tsx` — todas as páginas:

| Schema | Onde | Conteúdo |
|---|---|---|
| `Organization` + `LocalBusiness` | Layout global | Nasus Digital, CNPJ, endereço Curitiba, sameAs apenas perfis corporativos (LinkedIn Nasus quando criado). **GitHub nunca entra no schema da Nasus** — ver Section 8.3. |
| `Person` | Layout global | Tiago Satur como author entity. sameAs decidido no caminho B da Section 8.3 (vazio por enquanto). |
| `Service` | Página principal | Cada serviço de Section 2 com `serviceType` + `areaServed` |
| `FAQPage` | Páginas com FAQ | Perguntas frequentes da seção Problema/Solução |
| `BreadcrumbList` | Páginas internas | Navegação clara pra crawlers |
| `BlogPosting` / `Article` | Posts do blog | Author Person + datePublished + image + headline |

**llms.txt** — padrão emergente (~10% adoção). Arquivo plain-text na raiz com mapa do site pra LLMs. Sinaliza "site pensado pra IA":

```
# Nasus Digital
> Sites e SEO para profissionais liberais brasileiros.

## Serviços
- [Presença Digital](https://nasus.digital#solucao): site rápido + responsivo
- [Presença Contínua](https://nasus.digital#solucao): SEO local + GMB mensal
- [AEO](https://nasus.digital#solucao): otimização pra IA search

## Sobre
- [Fundador](https://nasus.digital#sobre): Tiago Satur, engenheiro de software

## Recursos
- [Blog](https://nasus.digital/blog): guias sobre sites, SEO, performance
```

**sitemap.xml** — auto-gerado pelo Next.js 16, com `hreflang` PT/EN.

**Submit nas ferramentas de webmaster:**
- Google Search Console (propriedade separada pra `/` e `/en`)
- Bing Webmaster Tools (Microsoft Copilot usa fortemente)
- IndexNow (notifica Bing + Yandex em tempo real de updates)

**Performance core** — já implementado parcialmente:
- PageSpeed/Lighthouse 95+ (atualmente 94 mobile, otimizar mais)
- LCP < 2.5s, INP < 200ms, CLS < 0.1
- `next/image` com lazy loading correto
- `next/font` zero layout shift

### 8.2 Camada de conteúdo (essencial pra ser citado)

A landing institucional sozinha **não** vai ser citada por IA. Quem cita = quem tem profundidade. Por isso o blog é peça crítica (Section 9).

**Princípios de escrita aplicados em qualquer conteúdo do site:**

| Técnica | Por que funciona | Impacto |
|---|---|---|
| H2 em formato de pergunta | LLMs procuram queries que casam | Base |
| Answer capsule (1ª frase = resposta) | LLMs extraem o primeiro parágrafo | Base |
| Tabelas pra comparações | LLMs extraem tabelas verbatim | Alto |
| Stats com fonte citada inline | Sinal de densidade factual | +30% |
| Expert quotes (mesmo do próprio autor) | Atribuição = proxy de credibilidade | +41% |
| Long-form 1500-3000 palavras | ChatGPT/Claude priorizam profundidade | Alto |
| Linguagem definitiva ("é", "garante") | Evita hedging que LLMs descartam | Médio |

### 8.3 Camada de autoridade (signals externos)

#### Modelo de marca — 3 caminhos considerados

A questão estratégica: **quanto o fundador (Tiago) deve aparecer no site da Nasus?** Em 2026-05-25, 3 cenários foram avaliados com input de ChatGPT, Gemini e análise interna:

| Caminho | Descrição | Quando faz sentido |
|---|---|---|
| **A — Marca anônima** | Sem nome, sem foto, sem seção Sobre, sem schema Person. Site se apresenta como marca corporativa pura. | Quando o fundador quer máxima privacidade, opera com várias pessoas, ou planeja venda/exit cedo. |
| **B — Híbrido institucional (adotado)** | Nasus é a protagonista; Tiago aparece na seção Sobre como prova de credibilidade (nome, foto, bio curta). Schema `Person` existe e conecta ao `Organization` via `worksFor`/`founder`, **sem `sameAs` pessoal**. | Quando se quer diferenciação contra agências genéricas sem virar founder-brand. Preserva opcionalidade futura. |
| **C — Founder-brand completo** | Tiago aparece com nome+foto+bio+schema Person+`sameAs` (LinkedIn pessoal, satur.dev). Blog assinado pessoalmente. Tiago é o produto. | Quando o fundador quer construir audiência pessoal, virar criador, ou maximizar AEO/E-E-A-T agressivamente. |

#### Decisão adotada: Caminho B — Híbrido institucional

A Nasus é a protagonista; Tiago aparece como prova de credibilidade na seção Sobre, mas o site não vira portfolio pessoal.

**Razão:** posicionamento "engenheiro solo, sem agência no meio" depende de o fundador estar visível (descarta A), mas o fundador não tem intenção de virar criador/influenciador (descarta C). B captura o diferencial sem custo de exposição pública intensa, e preserva a opção de migrar pra C depois com cirurgia simples.

**Implicações no schema e na operação:**

- **Regra firme: GitHub nunca entra no schema da Nasus**, em nenhum dos caminhos. GitHub é asset de empregabilidade/comunidade técnica do Tiago — não autoridade da Nasus. Cliente final (clínica, escritório) não entende e não usa. Mesmo se a Nasus migrar pra Caminho C no futuro, GitHub continua fora.
- **Schema Person (Tiago)** — existe e está conectado ao Organization via `worksFor`/`founder`. **Sem `sameAs` pessoal por enquanto** (LinkedIn pessoal e satur.dev). Adicionar quando houver LinkedIn corporativo da Nasus ou quando a opcionalidade de exposição pessoal estiver resolvida.
- **Organization entity uniforme** — Nasus Digital com mesmo nome, descrição, logo, email em todos os perfis: Google Business Profile, LinkedIn page (quando criada). `sameAs` da Org aponta pra perfis corporativos, não pessoais.
- **satur.dev (TikTok/perfil técnico pessoal)** — vive separado da Nasus, propósito distinto (reputação técnica pra empregabilidade / comunidade dev / SaaS futuro). **Não conectar formalmente no schema** da Nasus. Decisão de produzir conteúdo lá é independente.
- **Backlinks no nicho** — guest posts em sites de associações (OAB regional, sociedades odontológicas, ABO/SBD), podcasts de marketing pra clínicas. Estes apontam pra Nasus, não pra Tiago pessoa.
- **Brand mentions** — IA Search valoriza menções de marca mesmo sem link (sinal de awareness). Trabalhar Nasus Digital como termo de marca.

**Custo de reversão:**

- **B → C:** cirurgia simples. Adicionar URLs em `sameAs` no Person em `lib/jsonLd.ts`. Nada visual muda no site.
- **B → A:** cirurgia grande. Remover seção Sobre, foto, schema Person, reescrever copy "sem agência no meio" pra outra direção. Posicionamento muda.

Por isso B é a posição padrão — preserva ambos os movimentos.

## 12. Internacionalização (i18n) — Versão em Inglês

### Por que internacionalizar

O PLANO.md já prevê "expandir para mercado internacional". A versão em inglês abre dois caminhos:
1. **Mercado anglófono** — healthcare clinics, law firms, dental offices nos EUA/Reino Unido/Austrália pagam em USD/GBP e têm budget maior que o mercado BR para serviços de SEO local.
2. **Credibilidade** — site bilíngue sinaliza sofisticação técnica para qualquer prospect que pesquise a Nasus.

### Biblioteca: `next-intl`

Melhor suporte ao App Router do Next.js 15. Alternativas descartadas:
- `next-i18next` → projetado para Pages Router
- Solução manual → sem tipagem, sem middleware automático

```bash
pnpm add next-intl
```

### Estrutura de rotas

| URL | Locale | Público-alvo |
|---|---|---|
| `nasus.digital/` | `pt` (default) | Brasil — sem prefixo de URL |
| `nasus.digital/en` | `en` | Internacional — inglês |

O idioma padrão (`pt`) fica na raiz sem prefixo. Isso preserva o SEO atual e não quebra links já compartilhados.

### Arquitetura de arquivos após migração

```
nasus/
├── messages/
│   ├── pt.json        ← todas as strings em PT
│   └── en.json        ← versão EN adaptada (não só traduzida)
├── i18n/
│   ├── routing.ts     ← define locales, defaultLocale, pathnames
│   └── request.ts     ← config do next-intl para Server Components
├── proxy.ts           ← detecção de Accept-Language + redirect (Next.js 16: proxy.ts substitui middleware.ts)
└── app/
    └── [locale]/      ← layout.tsx e page.tsx migram para cá
        ├── layout.tsx
        └── page.tsx
```

Componentes em `components/` não precisam mudar de lugar — só chamam `useTranslations` dentro deles.

### Passos de implementação

**1. Instalar e configurar o roteamento**

Criar `i18n/routing.ts`:
```ts
import { defineRouting } from 'next-intl/routing';

export const routing = defineRouting({
  locales: ['pt', 'en'],
  defaultLocale: 'pt',
  localePrefix: 'as-needed', // PT fica em /, EN fica em /en
});
```

**2. Criar middleware de detecção automática**

`middleware.ts` usa `Accept-Language` do browser para redirecionar usuário inglês para `/en` automaticamente.

**3. Mover `app/layout.tsx` e `app/page.tsx` para `app/[locale]/`**

O `layout.tsx` passa a receber `params.locale` e injeta:
- `<html lang={locale}>` dinâmico
- `<link rel="alternate" hreflang="pt" href="https://nasus.digital/" />`
- `<link rel="alternate" hreflang="en" href="https://nasus.digital/en" />`
- `<link rel="alternate" hreflang="x-default" href="https://nasus.digital/" />`

**4. Extrair strings para `messages/pt.json`**

Cada seção vira uma namespace:
```json
{
  "hero": {
    "headline1": "Seu concorrente está na primeira página do Google.",
    "headline2": "Você, não.",
    "subheadline": "Sites que ranqueiam, convertem e trazem clientes reais.",
    "ctaPrimary": "Ver como funciona",
    "ctaWhatsapp": "Falar agora"
  },
  "problem": { ... },
  "solution": { ... },
  "proof": { ... },
  "process": { ... },
  "about": { ... },
  "cta": { ... },
  "header": { ... },

}
```

**5. Adaptar copy para `messages/en.json`**

Não é tradução literal — é adaptação para o mercado anglófono:

| Conceito PT | Adaptação EN |
